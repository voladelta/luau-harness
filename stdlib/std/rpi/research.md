# Research
Answer the supplied neutral questions using the current bounded project source index, relevant source and approved read tools. Batch related reads/searches and focus on evidence that affects the later design. Explain existing behavior with exact project files and symbols, tests and constraints. Separate observations, hypotheses and unresolved assumptions. Do not replace present-state research with proposed implementation.

An empty project needs a short factual report: there is no current implementation to analyze. Identify established constraints and useful source pointers, record reversible assumptions, and continue. Runtime/tool availability that cannot be established from project evidence should be validated with sh in implementation; inspect stages cannot execute it. Harness logs, artifact views and system/package-manager directories are outside this project-source investigation. Record unavailable sources and checks not run honestly; essential missing information can create an input gate, while routine choices remain autonomous. Submit the research document once the design-relevant questions are answered or clearly bounded.
