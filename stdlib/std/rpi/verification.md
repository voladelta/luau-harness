# Verification and diff review
Independently review the resulting source against acceptance requirements and design. Run every frozen program-design check with its exact command, cwd and timeout using sh(command,{cwd=cwd,timeout=timeout}); record returned operation_id values in submission evidence. All evidence must come from THIS verification stage. A successful tool call is not proof of success: inspect exit status, timeout and output. Do not substitute `true` or weaker commands. Perform checks after final source edits; any edit invalidates older evidence. Prefer leaving source fixes to the repair stage so failures get an explicit record.

Submit `findings={}` only if there are no actionable failures. Otherwise include a findings array of specific issues with paths and expected behavior; the workflow will repair and verify again. The host independently checks receipts and source freshness. Required manual checks not yet confirmed must be listed as `manual_check_ids={"id"}` plus concrete questions; never silently waive them. Document passed, failed, skipped, manual and waived checks distinctly, along with implementation limitations and review findings.

Owner answers about manual checks are evidence to assess, not automatic success. If an owner reports failure, record an actionable finding. If an answer is unclear, ask a specific follow-up. Explicit owner waivers are distinct from passing checks and must remain listed as waived. Only list still-unresolved manual_check_ids; confirmed results should be documented with their owner source.
