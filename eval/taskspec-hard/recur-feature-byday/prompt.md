This is a small Python library for recurring calendar events (`recur/`, a subset of RFC 5545 recurrence rules; tests in `tests/`, run with `python3 -m unittest discover -s tests -t .`).

Users need rules like "the last Friday of every month", "the fourth Thursday of November" and "the last working day of the month". Extend the rules as follows (the RFC 5545 meaning applies wherever this leaves something open):

1. **BYDAY ordinals.** A BYDAY entry may have an ordinal in front of the weekday: `1MO` is the first Monday, `-1FR` the last Friday, `+2TU` the second Tuesday (a leading `+` is accepted). The ordinal must be between 1 and 53 in absolute value; `0`, a larger value or anything that is not an integer raises `ValueError`. Ordinals are only allowed with `FREQ=MONTHLY` or `FREQ=YEARLY`; any other frequency raises `ValueError`. Plain and ordinal entries can be mixed (`BYDAY=1MO,-1MO,WE`).
   - `MONTHLY`: the n-th such weekday of each month. A month without one (e.g. `5MO` in a month with four Mondays) has no date for that entry.
   - `YEARLY` with `BYMONTH`: the n-th such weekday within each listed month.
   - `YEARLY` without `BYMONTH`: the n-th such weekday of the whole year (`20MO` is the year's 20th Monday). In this case a plain weekday also means every such weekday of the whole year.
   - Entries without an ordinal keep their current meaning everywhere else.
2. **Negative BYMONTHDAY.** Values from -1 to -31 count from the end of the month (`-1` is the last day, `-2` the day before). They are allowed wherever BYMONTHDAY is allowed today. `0` and values beyond ±31 raise `ValueError`. A day that does not exist in a month (for example `-31` in April) is skipped for that month.
3. When both `BYMONTHDAY` and `BYDAY` are given, a date must match both (as today), ordinals included.
4. **BYSETPOS.** `BYSETPOS=1,-1` takes a list of non-zero integers between -366 and 366 (other values raise `ValueError`). It is only allowed with `FREQ=MONTHLY` or `FREQ=YEARLY`, and only together with `BYDAY` or `BYMONTHDAY`; otherwise `ValueError`. For each period (each month for MONTHLY, each year for YEARLY), take the sorted set of dates the other rule parts produce, keep only those at the given 1-based positions (negative positions count from the end; positions beyond the set are ignored; a date selected twice appears once) and use them in date order. This selection happens before dates earlier than the start date are dropped and before `COUNT` and `UNTIL` are applied. Example: `FREQ=MONTHLY;BYDAY=MO,TU,WE,TH,FR;BYSETPOS=-1` is the last weekday of each month.
5. **`format_rule`** writes ordinals without a `+` (`2TU`, `-1FR`), keeps BYDAY entries in the order they were given, writes negative month days as they are, and places `BYSETPOS` right after `BYDAY`. `parse(format_rule(r))` must describe the same rule.
6. **`describe`** names an ordinal entry like this: `the first Monday`, `the second Monday`, ..., `the fifth Monday`, then with numerals from 6 on (`the 6th Monday`, `the 21st Monday`, `the 22nd Monday`, `the 23rd Monday`, `the 11th Monday`), `the last Friday` for -1, and `the second to last Friday`, `the 6th to last Friday` and so on for other negative ordinals. Entries are sorted by weekday, Monday first; entries for the same weekday stay in rule order. Entries without an ordinal still show only the weekday name. `describe` must not fail on any valid rule.
